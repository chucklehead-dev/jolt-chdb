**Does the fix resolve the prior finding?** Mostly yes. The old blanket `(catch Throwable ...)` let any unrelated exception masquerade as the intended rejection. The new `rejects?` catches only `AssertionError` and requires the exception's `.getMessage` to contain the `intended-check` marker (`str/includes?`). A wrong-cause failure now either (a) throws a different exception type, which is uncaught and crashes the run, or (b) throws an `AssertionError` whose pr-str'd form lacks the marker, making `rejects?` return `false` and failing the outer `(assert ...)`. Either way the silent wrong-cause pass is eliminated. The added synthetic valid10k positive control is honestly labeled (comment: "not evidence of real 10k recovery") and exercises the 2x-scaled geometry path.

**Remaining defect — marker matching is substring matching against compound assert forms, not per-field isolation.** Several target assertions in `validate-rich-sdk-scaling-20261019.clj` bundle multiple distinct fields into one `assert`/`and`/`mapv` expression whose Clojure-generated failure message is just the pr-str of the whole form:
- Line 28: `(every? #(and (<= 1 (:rows %) 5000) (:ok %)) batches)` — contains both `:rows` and `:ok`.
- Line 38: `(and (:passed r) (:full-physical-rows-equal r) (:typed-values-status r) (= [...] (mapv r [:rows :groups :trace-count :per-record-multiplicity])))` — contains `:rows`, `:groups`, `:trace-count`, `:per-record-multiplicity`, `:full-physical-rows-equal`, `:passed`, `:typed-values-status` all in one message.

Because the test checks `str/includes?` on marker text, any failure of these compound asserts satisfies *every* marker drawn from that same form (e.g. the `":groups"`, `":rows"`-in-reader, `":full-physical-rows-equal"`, and `":per-record-multiplicity"` negative controls all trip the same line-38 assert). A mutation intended to isolate one field's validation could actually be masking a defect in validating a sibling field bundled in the same assert — the negative controls are not mutually discriminating for fields sharing a compound assertion. This is a weaker, narrower version of the original issue: not a wrong-cause pass, but an under-specified one.
